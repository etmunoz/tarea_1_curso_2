EL COORDINADOR: LA PRUEBA FINAL CON TODOS LOS AGENTES DE TODOS
-------------------------------------------------------------
Como cierre del taller creamos un COORDINADOR web y lo dejamos corriendo de forma
PERMANENTE en nuestra VPS, accesible por HTTPS en:

    https://coordinador.etmk.cl        (usuario: coordinador + clave)

¿Qué es? Un "supervisor A2A": recibe una pregunta en lenguaje natural, lee las
fichas (Agent Cards) de TODOS los agentes del catálogo, DECIDE a cuál corresponde,
se la envía por A2A y muestra la respuesta junto con el ruteo que hizo.

Lo importante: con este coordinador hicimos la PRUEBA FINAL end-to-end reuniendo
en un mismo lugar a los agentes de los TRES integrantes del grupo (y de más de
uno), sin importar en qué computador corre cada uno:

  - Agentes LOCALES del VPS:
      * Agente de cocina chilena   (recetas + costeo en CLP)
      * (según configuración, también Ezequiel y/o Tomás pueden correr locales)

  - Agentes REMOTOS por túnel de Cloudflare, que se agregan desde la propia web
    en la sección de Configuración (engranaje ⚙️), pegando la URL de cada uno:
      * Agente de Ezequiel     — IA / Machine Learning           (Mac)
      * Agente de Tomás        — Reiki, con RAG                   (Windows)
      * Agente Fabio           — bioinformática                  (Fabio)
      * ProteinMAN             — IA / Data Science en bioinfo.   (Fabio)
      * agente_meteorologo     — pronóstico del clima            (Gustavo)

Así, un ÚNICO coordinador enruta a Ezequiel, Tomás, Fabio, Gustavo y ProteinMAN
estén donde estén: basta cambiar su URL en ⚙️. El panel derecho ("Ruteo del
coordinador") muestra, por cada pregunta: el agente elegido por el supervisor, el
motivo, el camino del grafo (guardia_entrada -> supervisor -> agente_local /
agente_remoto -> guardia_salida) y los "Antecedentes del acceso" (si fue local o
remoto, el grafo, el endpoint, el host y la IP a la que realmente se accedió).

De esta forma validamos la interoperación A2A completa: desde un mismo coordinador
en PRODUCCIÓN (HTTPS) preguntamos y enrutamos a los agentes de todos los
integrantes, consumiéndolos en vivo, y lo hicimos desde DISTINTAS máquinas (nuestro
Mac y el PC de Gustavo). El coordinador trata cada respuesta remota como un DATO
(guardrails), nunca como instrucciones.

PARA CORRER EL PROYECTO (carpeta proyecto/)
-------------------------------------------
Requisitos: uv (https://docs.astral.sh/uv/), Python 3.13, Docker (para el RAG),
y una GOOGLE_API_KEY de Gemini (https://aistudio.google.com/apikey).

    cd proyecto
    uv sync
    cp .env.example .env            # pega tu GOOGLE_API_KEY en el .env
    docker compose up -d            # levanta Redis (RAG del agente de Tomás)
    uv run langgraph dev            # publica los agentes en http://127.0.0.1:2024
    uv run python tools/configurar_fichas.py   # aplica las fichas (Agent Cards)

Probar / evidencias:
    uv run pytest
    uv run python tools/guardar_evidencias.py --etiqueta mac

Coordinador, app web y túnel Cloudflare (plug and play por equipo):
    Mac:      scripts/mac_coordinador.sh · scripts/mac_app.sh · scripts/mac_tunel.sh
    Windows:  scripts/win_coordinador.ps1 · scripts/win_app.ps1 · scripts/win_tunel.ps1

Guía completa paso a paso: carpeta "taller-a2a/" dentro de proyecto/.
